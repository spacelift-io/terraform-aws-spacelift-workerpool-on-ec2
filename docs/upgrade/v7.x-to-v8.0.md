# Upgrading v7.x → v8.0

## What changed

Worker termination is now atomic, and scale-downs drain gracefully through the ASG lifecycle hook.

- **The autoscaler uses `TerminateInstanceInAutoScalingGroup`.** The previous detach-then-terminate sequence
  could leave an instance detached-but-alive — capacity decremented, instance never terminated, worker still
  registered — if anything failed between the two calls (e.g. a client-side timeout after the detach already
  succeeded). The single atomic call removes that failure mode.
- **The lifecycle manager is now deployed whenever the autoscaler is enabled** (previously only when
  `instance_refresh` was set). Scale-down terminations flow through the `EC2_INSTANCE_TERMINATING` hook, which
  drains the worker before the instance is terminated.
- **One shared IAM role for both Lambdas.** The autoscaler and lifecycle manager previously created separate
  roles; they now share a single role (`<base_name>-lambda`).

## How draining protects in-progress runs

Any ASG-initiated termination (autoscaler scale-down, instance refresh, AZ rebalance, manual terminate) now flows through the `DrainWorkerLifecycleHook`.
The lifecycle manager drains the worker so no new run can land on it, and while a run is still in progress it holds the instance in `Terminating:Wait`, re-checking with exponential backoff and heartbeating the hook on each check.
The instance is only released once the worker is idle.

`lifecycle_hook_timeout` (default 300s) is the hook's *heartbeat* timeout, not the total drain budget: heartbeats reset it on every re-check, so the default accommodates runs of any realistic length.
The total wait is bounded by the lifecycle manager's retry budget (roughly 90 minutes at the default) and AWS's cap of 100x the heartbeat timeout or 48h, whichever is smaller.
Runs longer than that bound are killed when the hook expires.

The autoscaler itself never targets busy workers during scale-down: it drains a candidate, verifies it is still idle, and only then terminates.
A worker that picked up a run in the meantime is un-drained and skipped.

## Requirements

- Autoscaler **≥ v2.8.0** (the first release issuing `TerminateInstanceInAutoScalingGroup`). Automatic when
  `autoscaling_configuration.version = "latest"`; pinned versions must be bumped to ≥ v2.8.0.

## Action required

On the next apply, existing autoscaler deployments will:

- Create the lifecycle manager (SQS queue + Lambda) and a `DrainWorkerLifecycleHook` on the ASG.
- Replace the two separate Lambda IAM roles with one shared role; the Lambdas update in place.

Review the plan before applying.

**Manual cleanup.** Any instance left *detached but not terminated* by a previous autoscaler version is not
reaped automatically — the new code no longer creates this state, but it also no longer cleans up pre-existing
ones. Find and terminate them manually:

```sh
aws ec2 terminate-instances --instance-ids <id>
```

## Note

Credentials were already required for the autoscaler, so no new credentials are needed — the lifecycle manager
reuses the same `spacelift_api_credentials`.
