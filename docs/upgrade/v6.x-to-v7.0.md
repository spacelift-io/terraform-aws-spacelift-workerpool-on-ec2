# Upgrading v6.x → v7.0

## What changed

Environment-variable handling was unified into a single `env_vars` variable. The separate `secure_env_vars`
and `autoscaler_extra_env` variables were removed, and `secret_env_var_arns` was added for referencing
existing Secrets Manager secrets.

## Action required

Migrate your variables:

```hcl
# before
secure_env_vars = {
  SPACELIFT_TOKEN = "..."
}
autoscaler_extra_env = {
  LOG_LEVEL = "info"
}

# after
env_vars = {
  SPACELIFT_TOKEN = { value = "...", sensitive = true }
  LOG_LEVEL       = { value = "info" }
}
```

- `secure_env_vars` (always secret) → `env_vars` entries with `sensitive = true`.
- `autoscaler_extra_env` (plain) → `env_vars` entries with just `value`.
- `secure_env_vars_kms_key_id` is unchanged.

## New

- `secret_env_var_arns` — map of env var name to an existing Secrets Manager secret ARN, for values that
  already live in Secrets Manager (Terraform never reads them).

> Note: `secret_env_var_arns` and `sensitive` env_vars currently apply to **EC2 workers only** — the
> autoscaler and lifecycle manager Lambdas don't resolve arbitrary secret env vars yet, so for the Lambdas
> these are placeholders and will likely be reworked or deprecated. This does not affect the Lambdas'
> operation: they authenticate with the Spacelift API key, delivered separately via SSM. Plain `env_vars`
> work on all components.
