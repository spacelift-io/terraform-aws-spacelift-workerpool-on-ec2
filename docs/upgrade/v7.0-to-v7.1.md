# Upgrading v7.0 → v7.1

## What changed

Large CA bundles now work on the autoscaler **and** lifecycle manager Lambdas. The bundle is stored in
Secrets Manager and fetched at runtime, so it is no longer subject to AWS's 4KB Lambda environment variable
limit (the previous `SPACELIFT_CA_BUNDLE` env var would fail to deploy with a large chain).

- **New `ca_bundle` variable (top-level).** Base64-encoded PEM trusted across the whole pool — EC2 workers
  (OS trust store) and both Lambdas (via Secrets Manager). Takes precedence over
  `selfhosted_configuration.ca_certificates`.
- **`autoscaling_configuration.ca_bundle` is deprecated** but still honored as a fallback.
- **Removed the unused AWS Parameters & Secrets Lambda extension layer.** It was attached but never read by
  either function. No action needed.

## Requirements

- Autoscaler **≥ v2.7.0** (the version that reads the CA bundle from Secrets Manager). Automatic when
  `autoscaling_configuration.version = "latest"`; pinned versions must be bumped to ≥ v2.7.0.

## Action required

None for existing configs. Optionally move `autoscaling_configuration.ca_bundle` to the top-level
`ca_bundle` so it also covers the lifecycle manager:

```hcl
# before
autoscaling_configuration = { ca_bundle = base64encode(file("ca.pem")) }

# after
ca_bundle = base64encode(file("ca.pem"))
```

## Note

When `ca_bundle` is set and the autoscaler or lifecycle manager is enabled, the module creates one
Secrets Manager secret (`<base_name>-unified-secret`).
